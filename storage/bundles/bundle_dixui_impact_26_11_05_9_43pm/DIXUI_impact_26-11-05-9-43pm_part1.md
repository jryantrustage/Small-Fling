## Architecture

This is a **DIstribution eXperience UI** React app that renders insurance application flowsdriven by product configuration from a backend ApI called InsuranceApp.

### Component Structure - Atomic Design

Components live in 'src/components/' and follow atomic design:

- **atoms/** - Simple UI elements and modal bodies (e.g., 'LoadingIcon', 'Stepper', ‘EditCoverageModalBody')
                                                                                ‘TitleBar'))
- **organisms/** - Complex sections (e.g., ‘GlobalHeader', 'DynamicFormSimple', 'FinalRateCard')
- **pages/** - Full page views ('ApplicationFlow', 'FinalRate', 'SummaryPage', ‘ApplicationResume‘)

Each component is a folder with co-located files:

```
ComponentName/
     ComponentName.tsx  # Arrow-function component
    styles.ts # Styled-components (sC-prefixed)
    types.ts  # Typescript interfaces
     index.ts # Barrel export
     ComponentName.test.tsx # Jest + RTL tests
    ComponentName.stories.tsx # Storybook (these may or may not exist today; for future
```

### State Management - React Context

All app state is managed via React Context (no Redux/Zustand). Key contexts in 'src/contexts/':

- **AppContext** - Logged-in user (from localstorage 'CACHED_USER'). The agent experience is aagent that manages a JwT state. A typical user is a customer that is authenticated with anactive session
- **TenantContext** - Tenant details and branding (fetched on mount). This stays true throughthe life of the web experience.
- **InsuranceAppContext** - Current insurance application state
- **AppBrandingContext** - Cobranding partner info (from 'pid' query param)
- **ErrorContext** - Form validation errors by form key
- **FooterContext**, **TitleBarContext** - Page layout state
- **UserContext** - Auth tokens from cookies -→ sessionstorage
- **CommonAPIContext** - API implementations for the commonui library

The provider nesting order in 'App.tsx' is significant - outer providers supply data to innerones.

### API Layer

- **No axios or React Query in use** - data fetching uses a custom 'fetch' wrapper at'src/utils/api-client.ts'('restfulApi()')
- Auth: JwT from localstorage, with 'x-api-key', 'x-role-groups', 'x-timezone','x-correlation-id' headers
- 4o1 responses throw a "session timeout" error
- Service files in 'src/api/' export plain objects with async methods (not classes)
- Environment config: production reads 'window.CoNFIG_DIxUI'; development reads 'process.env'

### The ‘commonui' Library

This app heavily depends on 'commonui' - an internal shared uI library providing:

- **Theme system**: 'Theme.getColor()', 'Theme.getFontstyles(), 'Theme.getMediaQuery()',"Themewrapper'
- **Components**:‘Icon',‘CoreButton',‘Markdown', modals ('ModalProvider',‘useConfirmModal'),notifications
- **API context**: ‘APIContext' that ‘CommonAPIContext' implements
- **i18n base translations**: merged with app-specific translations
- **Types**: 'LoanApplicationEntities', 'NotificationEntities', 'IThemeColors'

when using theme utilities, import from 'commonui', not from styled-components' 'ThemeProvider'.

### Routing

React Router v6 with routes defined as an enum in 'src/components/Router/ListedRoutes.ts':

   typescript
enum ListedRoutes {
    app = '/application/:insuranceAppId',
    appResume = '/application',
    notFound = '/error',
    teststartApp = '/test/start-app',
    summary = '/summary/:insuranceAppId',
}
```

### i18n

Uses i18next (English only today). Translations merge 'commonui' base keys with app-specifickeys from 'src/i18n/en.ts'.

o - In components: 'const { t  = useTypedTranslation()' - provides type-safe translation keys
- Outside components: ‘nonHookTypedTranslation(key)'
- Keys follow ‘SECTION_DESCRIPTION' naming (e.g.,‘FINAL_RATE_COVERAGE_HEADER')

## Key Conventions

### Styling

- All styles use **styled-components** in a co-located 'styles.ts' file
- Styled component names use **'sc' prefix**: 'SCRate', 'SCRateHeader', 'SCInfo'
- Use 'Theme.getColor()' and 'Theme.getFontStyles()' from ‘commonui' - don't use raw color orfont style values
- Responsive breakpoints: 375px (SM), 804px (MD), 1080px (LG)
- 'styled-components/macro' is **banned** - import from ‘styled-components' directly

### TypeScript

- 'baseUrl' is 'src' - imports are absolute from 'src/' (e.g., 'import X from'contexts/AppProviders'')
- Strict mode enabled
- Interfaces prefixed with 'I' (e.g.,'IInsuranceApp', 'ITenantContext')
- Component props defined in co-located 'types.ts'

### Testing

  **Framework**: Jest + React Testing Library + jest-axe
- **Accessibility**: every component test should include an axe violation check
- **Test wrapper**: use 'TestProviders' from 'src/tests/TestProviders.tsx' for components thatneed context
- 'react-i18next' is mocked globally in 'setupTests.ts' - tests see translation keys, nottranslated text
- - Test file naming: 'ComponentName.test.tsx' co-located with the component

### ESLint

  Extends Airbnb + Prettier
  Components must be **arrow functions** (enforced by 'react/function-component-definition')
- $ Single quotes, Jsx single quotes, 4-space indentation, 12o char line width
  Unused vars prefixed with _' are allowed
  Named exports preferred over default exports
